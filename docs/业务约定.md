# 当前业务约定

安排中的 people 是计划机会，不表示已曝光；exposures 单列实际场馆。成交、退款和投诉按原业务机会归属，金额为分。campaign 是扩大（放量）申请与审批，重复批准不会重复发券；原始 totals 只是账面汇总，不作统计推断。实验分析以预先安排的活动机会为随机化单位，结论只来自预先注册的计划与判断记录。

## 数据与一致性

金额均为整数分；日期使用零补齐的日期或同一时区时间字符串，跨时区输入应由调用方先规范化。纯日期在分析中等同于该日 UTC 零点。所有 ID 为业务编号。写入会增加修订并保留旧值，历史 `recorded_at` 是登记时间，不等于事实发生时间；不能据此推断未观测到的业务事实。

单次业务操作是一个事务，失败不留下中间结果；整份回放按顺序逐项执行，前一项成功不会因为后一项失败而撤销。现有重复编号拒绝语义及已完成状态的重试语义由业务操作维护。操作台 JSON 中 `results` 是操作结果，`state` 为当前业务记录；历史以 `Store.history` 查询，当前状态与历史不能混为一谈。

## 实验分析方法

- **预先注册**：`experiment.plan` 在任何曝光、成交之前冻结活动范围、主要收益指标、经营限制（上限型）、最低有意义效果和允许查看结果的节点。已产生曝光或成交的机会不能再注册；注册后指标与限制不可更换。
- **ITT（意向治疗）口径**：判断以安排时的活动臂/对照臂为准，未曝光者保留在原臂，不单独分析核销者子集；成交按原业务机会归属。实际未曝光只登记覆盖率 caveat，不改变分组。
- **聚类与重复球友**：同一次机会（同场同行者）是一个聚类，主分析用机会层面的 CR1 聚类稳健标准误与 t 区间，不把同场各人当作独立证据。同一球友跨机会重复出现时，另做人物层面聚类的敏感性分析；同时出现在两臂的球友从该敏感性分析剔除并计数。跨臂球友比例超过 20% 时，独立证据不可辨认，判断强制 `reserve`。
- **跨馆与干扰**：跨馆曝光不重新分组，只在 caveat 中登记数量与比例；比例超过 20% 时认为馆间干扰无法辨认，判断强制 `reserve`。
- **信息时间（as-of）**：每次 `experiment.evaluate` 带 `as_of`，只纳入发生时间不晚于该节点的曝光、成交与退款；更晚的成交和退款不进入本次计算，只在 caveat 中说明金额或笔数，不能偷渡到较早判断。
- **查看纪律**：计划内节点的首次判断为确认性（`confirmatory=true`），多个节点按 Bonferroni 校正（alpha=0.05/节点数）。计划外查看会把计划标记为 `compromised`，其后所有判断只能是探索性，决策强制 `reserve`，原置信说法不得继续沿用。同一节点重复查看属于计划外查看。`experiment.close` 可提前关闭计划，若仍有未使用节点则标记 `closed_early`。
- **指标**：`net_revenue_per_slot`（每安排槽位净收入，分，退款后）、`complaint_rate`（有投诉槽位占比）、`discount_rate`（原价客挤占：非原价成交槽位占比）。比率类限制用差值的单侧置信上界与注册限值比较；收益用差值的单侧置信下界与最低效果比较。
- **决策**：收益与全部经营限制同时达标为 `supported`；任一未达标为 `not_supported`；证据不足（每臂聚类少于 2 个）、干扰不可辨认或判断不具确认性时为 `reserve`。每次判断同时给出点估计、置信区间、样本概况、caveat、保留原因和人物/槽位层面的敏感性结果。

## 判断依据与放量控制

- 扩大申请 `campaign.request` 必须引用一次 `experiment.evaluate` 判断，且申请机会与计划范围一致。`not_supported` 或 `reserve` 时负责人可以人工放行，但必须 `manual_override=true` 并写明 `override_reason`；限制依据与判断快照随申请留存，不能跳过。
- 每次判断固化数据签名（覆盖范围内机会、成交、退款的编号与修订号）。审批时重新计算签名：安排修订、补登记曝光、新增退款等任何变化都会使签名失配，审批直接阻断且不产生部分写入，待执行申请须在重新判断后重新申请。
- 已执行（已批准）的决定不被后续数据变化撤销，仍可通过 `Store.history` 与引用的 evaluation 看到当时依据；但旧依据不能用于新的扩大申请。
- 判断、重复查看、审批失败后的重试都不发券；只有审批成功时按 `coupon_count` 一次性发券，重复审批返回原记录、不额外发券。

直接方法调用和本地操作台使用相同的业务服务。`data/demo.json` 展示一条包含预注册、计划内判断、caveat 与放量审批的正常经营路径，并不代表总体人群；它不适合用来宣称任何统计规律。扩展分析时应另外构造能辨别缺失、覆盖和信息时间的样本，不得把样本中的关联直接当成因果结论。
